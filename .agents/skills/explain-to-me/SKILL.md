# Explain to me

1. Explain for a technically strong professional who has not programmed. Define any necessary term.
2. Structure: what it does (1-2 sentences) → how, step by step → what could go wrong → how the tests check it.
3. Point to specific files and lines.
4. End with one question that checks understanding.
5. If the user cannot explain a change back in their own words, recommend not committing it yet, and note this in the session log.
